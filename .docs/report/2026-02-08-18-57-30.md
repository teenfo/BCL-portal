# BCL Portal 기획 대비 구현 분석 보고서

**분석 일시:** 2026-02-08 18:57:30

## 1. 분석 범위

- 기획 문서: `/.docs/README.md`, `/.docs/apps/**`, `/.docs/sitemap/bcl-portal-sitemap.md`, `/.docs/database.md`, `/.docs/security-auth.md`
- 구현 코드: `src/app/**`, `src/components/AuthGuard.js`, `src/lib/supabase.js`

## 2. 전체 요약

- **라우팅 구조는 기획과 대체로 일치**하나, 일부 핵심 경로가 누락되거나 다른 경로로 구현되어 있습니다.
- **회원 앱(`/apps`)은 데이터 연동이 가장 활발**하지만, 문서에 없는 테이블/컬럼을 광범위하게 사용합니다.
- **관리자 포털(`/admin`)은 UI와 일부 조회 기능이 존재**하나, 설정/정책/권한 등 기획된 다수 페이지가 누락되어 있습니다.
- **코치 앱(`/coach`)은 핵심 3~4개 화면만 구현**되어 있고 레이스 시스템은 미구현입니다.
- **키오스크(`/kiosk`)는 스캔 UI는 있으나 실제 검증/체크인 로직이 미연동**입니다.
- **Class Portal(`/class`)은 UI 중심의 목업 상태**이며 리더보드 등 일부 페이지가 누락됩니다.

## 3. 앱별 구현 현황 (기획 대비)

### 3.1 회원 앱 `/apps`

구현된 주요 경로
- `/apps/dashboard` 실데이터 로드 (sessions, notices, members + membership_plans 조인) `src/app/apps/dashboard/page.js`
- `/apps/schedule`, `/apps/schedule/:id` 예약 흐름 구현 (reservations 사용) `src/app/apps/schedule/page.js`, `src/app/apps/schedule/[id]/SessionDetailClient.js`
- `/apps/checkin` QR 생성 구현 `src/app/apps/checkin/page.js`
- `/apps/notices`, `/apps/notices/:id` `src/app/apps/notices/**`
- `/apps/notifications` `src/app/apps/notifications/page.js`
- `/apps/membership`, `/apps/membership/plans` `src/app/apps/membership/**`
- `/apps/bookings`, `/apps/bookings/:id` `src/app/apps/bookings/**`
- `/apps/facilities`, `/apps/facilities/:id` `src/app/apps/facilities/**`
- `/apps/support`, `/apps/support/:id` `src/app/apps/support/**`
- `/apps/profile`, `/apps/profile/security`, `/apps/profile/history/checkin`, `/apps/profile/history/billing` `src/app/apps/profile/**`

기획 대비 불일치/누락
- 문서의 `/apps/checkin/history`는 구현되지 않고 `/apps/profile/history/checkin`으로 대체됨.
- 문서의 `/apps/billing/payments`, `/apps/billing/help`는 미구현이며 `/apps/profile/history/billing`으로 대체됨.
- 문서의 `/apps/settings` 경로는 미구현.
- 문서의 `/apps/bookings/new/:sessionId` 미구현.

기능 수준 요약
- 대시보드/스케줄/공지/예약은 실제 Supabase 조회가 존재하지만, **테이블과 컬럼이 문서 SSOT와 다수 불일치**합니다.

### 3.2 관리자 포털 `/admin`

구현된 주요 경로
- 대시보드, 회원 목록/상세, 출석 로그, 예약, 세션 스케줄, 코치 관리, 공지/콘텐츠, 알림, 리포트, 감사 로그, 지원 등 다수 페이지 존재.
- 예시 파일: `src/app/admin/dashboard/page.js`, `src/app/admin/members/**`, `src/app/admin/attendance/page.js`, `src/app/admin/sessions/schedule/page.js`, `src/app/admin/content/**`, `src/app/admin/reports/**`, `src/app/admin/audit/**`, `src/app/admin/support/page.js`

기획 대비 불일치/누락
- Sitemap 문서에 있는 다음 경로는 코드에 없음:
  - `/admin/sessions/assignments`
  - `/admin/coaches/certifications`
  - `/admin/content/moderation`
  - `/admin/settings/policies`, `/admin/settings/memberships`, `/admin/settings/roles`
- `/admin/settings/facility`는 존재하지만 **Supabase 연동 없이 정적 폼**(`src/app/admin/settings/facility/page.js`).
- `/admin/checkin/qr`는 라우트는 존재하지만 기능 상세는 제한적.

### 3.3 코치 앱 `/coach`

## 4. 핵심 스키마/데이터 불일치

문서 SSOT `/.docs/database.md`와 코드 사용 테이블/컬럼 간의 차이:

- 코드에서 사용하지만 문서에 없는 테이블
  - `membership_plans` (`/apps/membership`, `/admin/billing/plans`)
  - `reservations` (`/apps/schedule`, `/apps/bookings`, `/coach/schedule/attendance`)
  - `checkins` (`/admin/dashboard`, `/admin/attendance`, `/admin/checkin/*`)
  - `facility_settings` (`/apps/facilities`)
  - `notifications` (`/apps/notifications`)
  - `support_tickets` (`/apps/support`, `/admin/support`)
  - `audit_logs` (`/admin/audit/actions`)
  - `profiles` (`/admin/checkin/scanner`)
- 문서에 있으나 코드에서 거의 사용되지 않는 테이블
  - `attendance` (문서) vs `checkins` (코드)
  - `transactions` (문서) vs `membership_plans`/`billing` 페이지는 별도 구조
- 컬럼 불일치
  - `members.membership_type`, `members.end_date` 등 코드 참조 컬럼이 문서 스키마에 없음.
  - `sessions.duration`을 코드에서 참조하지만 문서 스키마에 없음.

## 5. 인증/보안 관련 불일치

- `AuthGuard`는 `requiredRole`를 받지만 **실제 역할 검증 로직이 주석 처리되어 있음** `src/components/AuthGuard.js`.
- 로그아웃은 `from=admin|apps`만 처리하며 **coach/class 경로는 미지원** `src/app/auth/logout/page.js`.
- 문서에는 `AuthGuard`가 `/admin/*`, `/apps/*` 전체를 보호한다고 되어 있으나, 실제로는 **coach/class도 같은 가드가 적용**되어 있음 (문서에는 불명확).

## 6. QR 체크인 프로토콜 불일치

- 문서: `BCL_CHK:{user_id}:{expiry_timestamp}` + 5분 내 만료 검증
- 구현: `BCL_CHK:{member.id}:{now}` 형식이며 만료 검증은 없음, 30초마다 갱신 `src/app/apps/checkin/page.js`
- 키오스크 쪽 검증 로직이 없어서 문서의 “만료 체크” 흐름이 성립하지 않음.

## 7. 구현 품질 메모 (버그/리스크)

- `src/app/apps/schedule/page.js`에서 `router` 미정의 상태로 `router.push` 사용 → 런타임 오류 가능.
- `src/app/admin/checkin/scanner/page.js`는 `profiles` 및 `checkins` 테이블에 의존하지만 문서 스키마에 정의 없음.

## 8. 결론

현재 구현은 기획된 라우팅 구조를 상당 부분 따라가고 있으나, **데이터 스키마와 권한/보안, 핵심 기능의 실제 동작 면에서 큰 간극**이 있습니다. 특히 **SSOT 문서의 테이블 정의와 코드가 사용하는 테이블/컬럼의 불일치가 가장 큰 리스크**이며, QR 체크인과 레이스 시스템 같은 핵심 기능은 문서 수준의 설계에 비해 구현이 미완성입니다.

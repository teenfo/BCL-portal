## 1. 개요 및 배경

### 1.1 목적
BCL Portal의 루트 URL(`/`)에 접속했을 때 표시되는 **피트니스 짐 홍보용 랜딩 페이지**를 구현한다.
현재 루트 페이지는 "프로젝트 초기화 완료"라는 개발 플레이스홀더만 존재하여,
일반 방문자(잠재 회원)에게 짐의 매력을 전달하고 회원 가입/로그인으로 유도하는 첫인상이 없는 상태이다.

**핵심 목적**:
- 비인증 사용자(잠재 회원)에게 짐의 가치 제안(Value Proposition)을 전달
- CTA(Call-to-Action)를 통해 회원 가입 및 로그인 유도
- 짐의 브랜드 아이덴티티(다크 모드, 오렌지 Primary) 확립
- SEO 최적화로 검색 엔진 노출 강화

### 1.2 현재 상태 (As-Is)

| 항목 | 상태 | 비고 |
|------|------|------|
| 루트 페이지 (`/`) | ❌ 플레이스홀더 | "프로젝트 초기화 완료" 텍스트만 존재 |
| 미들웨어 공개 경로 | ✅ 설정됨 | `/`는 PUBLIC_PATH, 인증 불필요 |
| 로고 에셋 | ✅ 존재 | `bcl-logo.svg`, `bcl-logo-white.svg`, `bcl-logo.png` |
| DB 신규 테이블 | 없음 | 기존 테이블 데이터를 읽기 전용으로 활용 |
| SEO 메타데이터 | ❌ 기본값 | `BCL Portal` 제목만 설정 |

### 1.3 핵심 제약 조건

| 항목 | 내용 |
|------|------|
| 렌더링 | CSR 기반 (프로젝트 규칙 준수) |
| 인증 | 비인증 상태에서 접근 가능해야 함 (PUBLIC_PATH) |
| DB 접근 | 읽기 전용 — `facilities`, `coaches`, `membership_plans` 등 기존 데이터 활용 |
| 반응형 | 데스크탑 + 모바일 모두 지원해야 함 (랜딩은 모바일 퍼스트가 아닌 양방향) |
| 디자인 | 프로젝트 디자인 시스템 준수 (Dark Mode, #ff6a00 Primary, Glassmorphism) |

## 3. 개선 설계 (To-Be)

### 3.1 핵심 설계 원칙
1. **첫인상 = 브랜드**: 방문 즉시 프리미엄 피트니스 짐이라는 인상 전달
2. **행동 유도 중심**: 모든 섹션이 최종적으로 "회원 가입" 또는 "로그인"으로 연결
3. **데이터 기반**: Admin에서 관리하는 실제 데이터(지점, 코치, 요금제)를 Read-only 표시
4. **성능 우선**: 이미지 최적화, lazy loading, 빠른 LCP(Largest Contentful Paint)
5. **CSR 렌더링**: 프로젝트 규칙 준수 — 동적 데이터는 클라이언트에서 Supabase SDK로 페칭

- **풀스크린 배경**: 그라데이션 + 모션 오버레이 (피트니스 분위기)
- **태그라인**: "Beyond CrossFit Limits" — 브랜드 메시지
- **서브카피**: "BCL과 함께 당신의 한계를 넘어서세요"
- **CTA 버튼**: `[무료 체험 신청]` (Primary) + `[로그인]` (Secondary/Ghost)
- **네비게이션 바**: 로고 + 섹션 앵커 링크 + [로그인] 버튼 (Sticky)

#### 🔶 Features Section (핵심 기능 소개)
- 3~4개의 아이콘 카드:
  - 📅 **스마트 예약** — 실시간 수업 예약 및 대기열
  - 📱 **QR 체크인** — 1초 터치로 출석 체크
  - 📊 **기록 관리** — 운동 기록 추적 및 리더보드
  - 🏆 **레이스 챌린지** — 실시간 로잉 레이스 대결
- Glassmorphism 카드 스타일

#### 🔶 Programs Section (프로그램 소개)
- 그리드 레이아웃 (2~3열)
- 프로그램별 카드: 이미지 + 제목 + 간단 설명
  - CrossFit WOD
  - Strength Training
  - Rowing / Endurance
  - Open Gym
- hover 시 상세 정보 확장 또는 오버레이

#### 🔶 Coaches Section (코치 소개)
- **DB 연동**: `coaches` 테이블에서 실시간 데이터 페칭
- 카드 UI: 프로필 이미지 + 이름 + 전문분야 + 한줄 소개
- Glassmorphism 카드 + hover 애니메이션
- 이미지 없는 코치는 기본 아바타 표시

#### 🔶 Pricing Section (요금 안내)
- **DB 연동**: `membership_plans` 테이블에서 실시간 데이터 페칭
- 요금표 카드 레이아웃 (3열: 기본/스탠다드/프리미엄 등)
- 각 카드: 플랜명 + 가격 + 기간 + 크레딧 수 + 특징
- 인기 플랜 하이라이트 (Primary 테두리)
- [지금 시작하기] CTA 버튼

#### 🔶 Facility Section (지점 안내)
- **DB 연동**: `facilities` 테이블에서 데이터 페칭
- 지점 정보 카드: 이름 + 주소 + 운영시간 + 연락처
- 지도 링크 (카카오맵/네이버지도 외부 링크)

## 4. 데이터베이스 변경 (필요 시)

### 4.1 마이그레이션 SQL
**DB 변경 없음** — 기존 테이블의 데이터를 읽기 전용으로 활용한다.

### 4.2 RLS 정책
기존 `coaches`, `facilities`, `membership_plans` 테이블의 **SELECT 정책**이 `anon` 또는 `authenticated` 역할에 대해 열려있는지 확인 필요.

```sql
-- 확인 쿼리: anon 역할의 읽기 권한
SELECT tablename, policyname, permissive, roles, cmd
FROM pg_policies 
WHERE schemaname = 'public' 
  AND tablename IN ('coaches', 'facilities', 'membership_plans')
  AND cmd = 'SELECT';
```

> ⚠️ 만약 `anon` 역할에 SELECT가 없으면, 랜딩 페이지에서 비인증 상태로 데이터를 읽을 수 없음.
> 이 경우 Phase 1에서 RLS 정책 추가가 필요.

```sql
-- 필요 시 추가할 RLS 정책 (anon 읽기 허용)
CREATE POLICY "anon_read_facilities"
    ON public.facilities
    FOR SELECT
    TO anon
    USING (true);

CREATE POLICY "anon_read_coaches"
    ON public.coaches
    FOR SELECT
    TO anon
    USING (true);

CREATE POLICY "anon_read_plans"
    ON public.membership_plans
    FOR SELECT
    TO anon
    USING (true);
```

## 7. 보안 고려사항

| 항목 | 상세 |
|------|------|
| **인증 불필요** | 랜딩 페이지는 PUBLIC_PATH로 이미 설정됨 |
| **데이터 노출** | 코치, 요금제, 지점 정보는 공개 데이터이므로 `anon` SELECT 허용 가능 |
| **민감 정보** | 회원 개인정보, 결제 정보 등 절대 노출하지 않음 |
| **CTA 링크** | `/auth/signup`, `/auth/login`으로만 연결 — 기존 인증 플로우 활용 |
| **XSS 방지** | DB 데이터를 렌더링할 때 React의 기본 이스케이핑(JSX)에 의존 |
| **anon RLS** | SELECT만 허용, INSERT/UPDATE/DELETE 절대 불가 |

## 10. 테스트 시나리오

### 정상 흐름
1. **비인증 사용자 접근**: `https://bcl.com/` 접속 → 랜딩 페이지 정상 렌더링 (인증 리다이렉트 없음)
2. **DB 데이터 표시**: 코치, 요금제, 지점 데이터가 Supabase에서 정상 로드되어 표시됨
3. **CTA 버튼 동작**: [무료 체험 신청] 클릭 → `/auth/signup`으로 이동
4. **로그인 버튼 동작**: [로그인] 클릭 → `/auth/login`으로 이동
5. **반응형 확인**: 모바일(< 768px) → 1열 스택 + 햄버거 메뉴, 데스크탑(> 1024px) → 3~4열 그리드
6. **스크롤 애니메이션**: 섹션 진입 시 fade-in 효과 정상 동작

### 예외 흐름
1. **DB 데이터 없음**: 코치/요금제/지점 데이터가 비어있을 경우 → Empty State 메시지 표시 ("곧 업데이트 예정입니다")
2. **네트워크 에러**: Supabase 연결 실패 시 → 정적 콘텐츠(Hero, Features, Programs)는 정상 표시, 동적 섹션만 에러 처리
3. **이미 인증된 사용자**: 로그인 상태에서 `/` 접근 → 랜딩 페이지 표시 (리다이렉트하지 않음) + 네비게이션에 "대시보드" 버튼 추가

# Documentation Sync Workflow

이 워크플로우는 소스 코드의 실제 구현 내용을 바탕으로 기획 문서(`.docs/sitemap/*.md`)를 최신화할 때 사용합니다.

---

## 🤖 멀티에이전트 배분

| 단계 | 담당 에이전트 | 모델 | 핵심 역할 |
|:-----|:------------|:-----|:---------|
| 1. 소스 코드 분석 | **Developer** | Sonnet 4.6 | 코드 분석, 변경 사항 추출 |
| 2. 기획 문서 대조 | **Developer** | Sonnet 4.6 | 코드-문서 불일치 식별 |
| 3. 기획서 업데이트 | **Developer** | Sonnet 4.6 | 문서 수정 |
| 4. 최종 정합성 확인 | **Architect** | Opus 4.6 (Thinking) | 전체 구조 일관성 검토, 승인 |

---

## 단계별 절차

### 1️⃣ 소스 코드 분석
**담당**: 💻 **Developer (Sonnet 4.6)**

- 최근 수정된 파일 또는 동기화가 필요한 대상 페이지의 `page.tsx` 및 관련 컴포넌트를 읽습니다.
- **Developer가 수행할 것**:
  - 실제 사용된 UI 텍스트, 데이터 필드, API 엔드포인트, 버튼 기능 추출
  - 기본 기능(로그인, 화면 표시, 링크 이동) 관련 변경 사항 우선 확인
  - 변경된 라우트, 컴포넌트, API 목록 정리

---

### 2️⃣ 기획 문서 대조
**담당**: 💻 **Developer (Sonnet 4.6)**

- `.docs/sitemap/**/*.md` 파일에서 해당 기능에 대한 기술 내용을 찾습니다.
- **Developer가 수행할 것**:
  - 현재 구현된 코드와 문서 사이의 차이점 식별
  - 누락된 필드, 변경된 라우트, 추가된 기능 목록화
  - Screen ID 매핑 누락 여부 확인

---

### 3️⃣ 기획서 업데이트
**담당**: 💻 **Developer (Sonnet 4.6)**

- 식별된 차이점을 바탕으로 기획 문서를 수정합니다.
- **Developer가 수행할 것**:
  - 단순한 기능 나열이 아닌, 실제 소스의 동작 방식이 정확히 기술되도록 작성
  - Stitch Screen ID 누락 시 추가
  - 변경된 API 엔드포인트, 데이터 필드 반영

---

### 4️⃣ 최종 정합성 확인
**담당**: 🏛️ **Architect (Opus 4.6 Thinking)**

- **Architect가 수행할 것**:
  - 수정된 문서가 사이트맵 전체 구조와 충돌하지 않는지 확인
  - 기본 기능 관련 문서가 정확히 반영되었는지 확인
  - 아키텍처 결정 사항이 문서에 반영되었는지 확인
  - 승인 후 `commit-bot` 스킬을 사용하여 문서 수정 내역을 커밋

---

## ✅ 체크리스트

- [ ] 변경된 파일 목록 파악 완료
- [ ] 코드-문서 불일치 항목 목록화 완료
- [ ] 기획 문서 업데이트 완료
- [ ] Screen ID 매핑 확인 완료

### Architect (Opus)
- [ ] 전체 Sitemap 구조 일관성 확인
- [ ] 기본 기능 문서 정확성 확인
- [ ] 최종 승인 완료
